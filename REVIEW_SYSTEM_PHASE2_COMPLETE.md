CREATE TABLE trade_reviews (
  id INT PRIMARY KEY AUTO_INCREMENT,
  trade_id INT NOT NULL,
  reviewer_id INT NOT NULL,
  rating INT NOT NULL (1-5),
  feedback TEXT,
  proof_url VARCHAR(255),
  is_camera_photo BOOLEAN DEFAULT FALSE,
  is_followup BOOLEAN DEFAULT FALSE,
  is_auto_generated BOOLEAN DEFAULT FALSE,
  rating_delta INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY unique_initial_review (trade_id, reviewer_id, is_followup),
  FOREIGN KEY (trade_id) REFERENCES trades(id),
  FOREIGN KEY (reviewer_id) REFERENCES users(id),
  INDEX idx_trade_id (trade_id),
  INDEX idx_reviewer_id (reviewer_id),
  INDEX idx_created_at (trade_id, created_at DESC)
);

### 3. Backend Handlers (`handlers/trade_review_handler.go`)

**New File with 6 Main Functions:**

#### a) `SubmitTradeReview()`
- Handles initial review submission
- Supports follow-up review submission
- Enforces photo evidence requirement for meetup/delivery trades
- Prevents overwriting initial reviews
- Calculates `rating_delta` for follow-ups
- Updates trades table with locks and timestamps
- Triggers auto-completion if both parties have reviewed

**Key Validations:**
- Rating must be 1-5
- Feedback required (non-empty)
- Photo required for initial reviews on meetup/delivery trades
- Photo must be taken with in-app camera
- Initial review already submitted → reject new initial
- No initial review → reject follow-up

#### b) `GetTradeReviewHistory()`
- Returns all reviews (initial + follow-ups) for a trade
- Sorted chronologically (oldest first)
- Includes reviewer name and avatar
- User must be trade participant (buyer or seller)

#### c) `GetReviewSummary()`
- Returns structured summary for both buyer and seller
- Includes:
  - `initialReview`: Locked first review
  - `latestReview`: Most recent review (may be follow-up)
  - `hasFollowup`: If follow-ups exist
  - `ratingTrend`: "up", "down", "stable", or "auto"
  - `ratingChange`: Delta from initial to latest
  - `followupCount`: Number of follow-ups

#### d) `getReviewSummaryForReviewer()` (Helper)
- Efficiently calculates review summary for one reviewer
- Queries initial review and latest follow-up
- Determines rating trend and delta

#### e) `AutoCompleteTradesJob()`
- Runs via scheduler (hourly recommended)
- Finds trades 3+ days old without complete reviews
- Creates default 5-star reviews for missing party
- Marks `auto_completed_at` timestamp
- Publishes SSE notifications to both parties

**Query Logic:**
1. Find trades: `status IN (...) AND DATE(NOW()) >= DATE_ADD(created_at, INTERVAL 3 DAY)`
2. Check: `buyer_rating IS NULL OR seller_rating IS NULL`
3. For each missing review: `createAutoGeneratedReview()`
4. If both complete: `completeTradeTransaction()`

#### f) `createAutoGeneratedReview()` (Helper)
- Checks if review already exists
- Inserts 5-star auto-generated review
- Sets lock on initial review
- Updates trades table with rating and timestamps

## Key Architecture Decisions

### 1. Immutable Initial Reviews
- **Mechanism**: `UNIQUE(trade_id, reviewer_id, is_followup=false)` constraint
- **Enforcement**: Backend check + lock flag in trades table
- **UX**: "LOCKED" badge on initial review in frontend

### 2. Follow-up Reviews
- **Mechanism**: `is_followup=true` allows multiple reviews per reviewer
- **Rating Delta**: Stored in `rating_delta` column for trend analysis
- **Display**: Shows both initial and latest, with ↑↓→ indicator

### 3. Auto-Completion
- **Trigger**: 3 days after trade creation
- **Default**: 5-star review for non-participating party
- **Marker**: `is_auto_generated=true` flag
- **Timestamp**: `auto_completed_at` records when auto-completed

### 4. Dynamic Trust Scoring
- **Latest Review Used**: Latest review rating (not initial) counts
- **Rating Delta Considered**: Trust score affected by rating changes
- **SQL View**: `latest_trade_review` enables efficient queries

### 5. Photo Evidence
- **Requirement**: Initial reviews on meetup/delivery trades
- **Validation**: `is_camera_photo=true` enforces in-app camera
- **Storage**: Reuses existing `/api/upload` endpoint
- **Display**: Lightbox modal in frontend
